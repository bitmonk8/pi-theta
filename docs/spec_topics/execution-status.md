# Execution Status

Live progress for running thetas ([RFC 0010](../rfcs/0010-live-execution-visibility.md), layers L0–L2). A running theta renders nothing between its binder echo and its final note by design — code-side tool calls add no conversation turn ([Tool Calls](./tool-calls.md)) and subagent-mode callees are content-unobservable by construction ([Slash-Command Invocation — SLSH-2](./slash-invocation.md#slsh-2)) — so the extension maintains a per-instance **execution-status bus** fed by existing runtime signals and rendered through best-effort operator-facing sinks. This page owns the bus contract, the producer set, the coalescing and emission bounds, the sink set and its degradation ladder, the verbosity model, and the telemetry-class partition the [SLSH-2 carve-out](./slash-invocation.md#slsh-2) binds. Nothing on this page adds a grammar surface, a conversation surface, or a diagnostic code (the registries are closed; see [Diagnostics — DIAG-2](./diagnostics/diagnostic-shape.md#diag-2)).

## Channel constraint

<a id="exst-1"></a> **EXST-1.** **Execution-status output is never a custom message.** Execution-status output MUST NOT be delivered through `pi.sendMessage` or any other custom-*message* channel: every custom message re-enters LLM context on every later provider call and can land between an assistant `tool_use` and its `tool_result`, durably corrupting the session ([Runtime event channel — custom-message persistence](./pi-integration-contract/runtime-event-channel.md#custom-message-context-entry-presupposition); bug 0469 is the incident record). The only permitted delivery surfaces are the transient UI surfaces enumerated at [EXST-8](#exst-8) (`ctx.ui.setStatus`, `ctx.ui.setWidget`, `ctx.ui.setWorkingMessage`) and the durable LLM-context-free entry channel ([Runtime event channel — PIC-71](./pi-integration-contract/runtime-event-channel.md#pic-71)). The entry channel is likewise the primary delivery surface for the operator-facing note classes (load/parse/type diagnostic batches, structural-change notes, binder-model recovery notes), per [Runtime event channel — PIC-72](./pi-integration-contract/runtime-event-channel.md#pic-72).

## Status bus

<a id="exst-2"></a> **EXST-2.** **One bus per extension instance.** The execution-status bus is constructed once per extension instance in the same composition pass that constructs the extension-instance-scoped invocation registry and the shared `Clock` ([Pi Integration Contract — `ActiveInvocationRegistry`](./pi-integration-contract/active-invocation-registry.md#active-invocation-registry); [PIC-12](./pi-integration-contract/host-interfaces-services.md#pic-12)), reaches its producers and sinks by explicit injection only — an implementation MUST NOT hold the bus (or any sink/producer state) as module-level or process-global state — and is torn down with the instance at `session_shutdown`, so a fresh `/reload` instance starts with a fresh bus and every sink un-degraded.

<a id="exst-3"></a> **EXST-3.** **Producer set (L0–L2).** Exactly four producer classes feed the bus in this release: (a) checkpoint-site telemetry ([EXST-4](#exst-4)); (b) invocation lifecycle, observed from the active-invocation registry and invoke provenance — the bus is a read-only observer and MUST NOT extend the registry's closed five-member entry shape ([Pi Integration Contract — `ActiveInvocationRegistry`](./pi-integration-contract/active-invocation-registry.md#active-invocation-registry)); (c) `par for` lane lifecycle — one lane slot per worker with states `queued | running | done | err`, observed from the worker pool whose width clamp is owned by [Control Flow — CTRL-2](./control-flow.md#ctrl-2); and (d) the child-activity tap ([EXST-5](#exst-5)). Producers publish synchronously and MUST NOT alter the observable behaviour of the surface they observe — registry `size()` transition points, lane claiming order, and checkpoint yield semantics are unchanged by observation.

<a id="exst-4"></a> **EXST-4.** **Checkpoint telemetry decorator.** Per-effect "current line" telemetry comes from a decorator over the production `Checkpoint` seam ([PIC-10](./pi-integration-contract/host-interfaces-services.md#pic-10)): `before(kind, site)` MUST publish `(invocationId, kind, site)` to the bus synchronously and then delegate, and the decorator MUST preserve the production wiring's per-kind yield semantics unchanged — `loop-iter` resolves on a macrotask turn, every other kind on the microtask queue — adding no awaited work before delegation. `loop-iter` publications MAY be throttled at the bus (they can be hot); the other four kinds are published unconditionally. The seam's no-observable-production-effect posture ([Cancellation — Race semantics](./cancellation.md), final edge-case bullet) is widened to "test/telemetry surface" by exactly this decorator and nothing else.

<a id="exst-5"></a> **EXST-5.** **Child-activity tap.** For depth-1 subagent children the bus MAY attach one additional listener to the child's existing stdout line pump beside the envelope scan ([Subagent — PIC-59](./pi-integration-contract/subagent.md#pic-59)); the tap MUST NOT consume, detach, or reorder lines the drive listener needs (stray-line tolerance and terminal-signal ordering are unchanged), MUST parse defensively with a per-line size cap, MUST project each recognised `--mode json` event to bounded class-1 fields at ingest (event kinds, counts, timing, tool *names*) and discard the remainder — prompt/response text, tool arguments, tool results, and thinking (class-3 fields per [EXST-12](#exst-12)) MUST NOT be retained, rendered, or forwarded — and MUST emit no diagnostic for unparseable, oversized, or unrecognised lines (they fold into the existing stray-line tolerance; the runtime registry is closed per [DIAG-2](./diagnostics/diagnostic-shape.md#diag-2)). At L3 the tap additionally recognises the `theta_progress` reserved-key line in its OWN parse ([EXST-15](#exst-15); [Subagent — PIC-74](./pi-integration-contract/subagent.md#pic-74)) — a class-2 payload the tap MUST re-clamp defensively before publishing (length clamps, control/ANSI strip, the per-child rate bound, and monotonic `seq`/latched `invocation_id` acceptance, per PIC-74's parent posture) — without widening `classifyChildStdoutLine` and without weakening any obligation in this rule: a `theta_progress` line that is unparseable, oversized, out-of-order, or otherwise malformed is an ordinary stray line.

## Coalescing and bounds

<a id="exst-6"></a> **EXST-6.** **Coalesced rendering.** Sink re-rendering MUST be coalesced: the bus schedules a render tick through the injected `Clock` seam ([PIC-12](./pi-integration-contract/host-interfaces-services.md#pic-12)) — never a bare global timer — with a minimum inter-render interval **anchored at the last completed render** — new dirt inside the window coalesces into the already-scheduled tick (drop the extra schedule, keep the deadline) rather than extending it, so continuous activity still renders once per interval instead of starving (contrast the event-anchored reload debounce at [Discovery — Re-reading & reload](./discovery/package-and-settings.md#caching-and-reload), whose quiet-period semantics are correct for reloads and wrong here) — and no render when nothing is dirty; rendering work runs on the tick, never inline in a producer's publish path. The 200 ms interval is an implementer tuning choice, not part of theta's observable contract; the *existence* of the minimum interval is normative. This coalescing governs the execution-status surface only and MUST NOT be extended to the diagnostic channel: duplicate diagnostic lines are re-emitted, not suppressed, per [Diagnostics — Re-scan deduplication](./diagnostics/diagnostic-shape.md#re-scan-deduplication). While any tracked invocation, `par for` lane, or tapped child is in a RUNNING state, the passage of a render interval itself constitutes dirt — a running row's rendered age is a function of the current time, so it advances with no producer publication at all — and the bus therefore keeps re-rendering at the coalescing cadence across quiet stretches (a code-only child that publishes nothing for minutes still shows a live age); once nothing is running and no ended node is still within its [EXST-7](#exst-7) linger, the interval carries no dirt of its own and the bus schedules nothing, so an idle bus stays render-free.

<a id="exst-7"></a> **EXST-7.** **Emission and memory bounds.** Bus state MUST be memory-bounded: an invocation's node is dropped when the invocation ends (a short "done"-flash linger is permitted), the set of tracked children per invocation carries a hard cap, and hot producer streams (`loop-iter`, child events) are throttled or counter-collapsed at the bus rather than queued unboundedly. The cap and linger values are implementer tuning choices; their existence is normative.

## Sinks and degradation

<a id="exst-8"></a> **EXST-8.** **Sink set and degradation ladder.** The L0–L2 sink set is: the footer heartbeat — `ctx.ui.setStatus("theta", …)` summarising active invocations from class-1 fields, plus `ctx.ui.setWorkingMessage` only while a driven prompt-mode turn is streaming (no working-indicator frames over silent tool calls); the invocation-tree widget — `ctx.ui.setWidget` at placement `belowEditor` with a height budget of 6 lines and overflow elided; and the durable entry channel ([Runtime event channel — PIC-71](./pi-integration-contract/runtime-event-channel.md#pic-71)). Every sink is best-effort under the optional-capability class ([Capability probe — PIC-73](./pi-integration-contract/capability-probe.md#pic-73)): each surface is presence-probed independently, every call is individually guarded, the first hard failure of a surface MUST permanently degrade that sink for the extension instance (a fresh `/reload` instance starts clean), a missing or failing surface MUST NOT refuse or degrade theta registration, and no diagnostic is minted for a degraded sink. `ctx.hasUI` is an advisory input only — it is `true` in TUI and RPC modes and `false` in `--mode json` and `-p` (pi `docs/extensions.md`, mode table) — and MUST NOT be the sole gate for any sink.

<a id="exst-9"></a> **EXST-9.** **Failure containment.** A throw from any sink call or producer hook MUST be caught at the bus boundary; it disables that sink (per [EXST-8](#exst-8)'s permanent-degrade rule) or drops that publication, and MUST NOT fail, delay beyond the coalesce tick, or otherwise perturb the theta drive — results, notes, cancellation behaviour, and timing semantics are unaffected by any sink outcome. The bus is fed synchronously (no awaits added on producer hot paths), and bus construction inside the extension factory's synchronous entry path MUST NOT make that path return a thenable.

## Verbosity

<a id="exst-10"></a> **EXST-10.** **`theta.progress` settings key.** The settings key `theta.progress` takes exactly one of the string values `"off" | "counts" | "names"`, defaulting to `names` when absent or invalid (defaulting at the read site, per the settings module's convention; an invalid value additionally draws the standard out-of-range settings diagnostic like every recognised scalar key — see [Discovery — Settings file reads](./discovery/package-and-settings.md#settings-file-reads)). The key selects the telemetry-class ceiling: under `off` no execution-status sink renders at all; under `counts` class-1 fields render with tool names withheld; under `names` the full class-1 field set renders ([EXST-12](#exst-12)). The key is read like every other settings key and is never written by the runtime.

<a id="exst-11"></a> **EXST-11.** **`/theta-status` view override.** The extension registers one non-theta-derived slash command, `/theta-status`, taking exactly one of `off | min | tree`; it adjusts the live instance's *view shape* only — session-scoped state that a `/reload` or fresh session resets — and the handler MUST NOT persist the choice to any settings file or other durable store. The registration joins the instance's own-registration ledger and the cross-format collision handling like every other registered command ([Registration steps — PIC-69](./pi-integration-contract/registration-steps.md#pic-69)), and the name is reserved against theta stems by the collision pass. View shape (`/theta-status`) and telemetry-class ceiling (`theta.progress`, [EXST-10](#exst-10)) are distinct axes: the command never widens what the settings ceiling withholds.

## Telemetry classes

<a id="exst-12"></a> **EXST-12.** **Three-class partition.** Everything the execution-status feature surfaces about a running invocation — including a subagent-mode callee — falls in exactly one of three classes, and the feature binds each: **class 1, telemetry** (event kinds, event counts, timing, source sites `file:line`, theta names, `par for` lane states, tool *names*) — default-on, ceiling-gated per [EXST-10](#exst-10); **class 2, author messages** (the payload of a `theta_progress` tool call — [EXST-13](#exst-13)) — a payload authored by the callee's *model* rides the same callable-set entry as an author-written call ([Parameters and Frontmatter — FRNT-2](./frontmatter/frontmatter-fields-a.md#frnt-2)) and MUST be rate- and length-clamped before rendering, and class-2 rendering MUST be disabled entirely under `theta.progress: off` ([EXST-14](#exst-14) owns the clamp values); **class 3, content** (prompt/response text, tool arguments, tool results, thinking) — the feature MUST NOT surface, retain, or forward class-3 fields on any sink at any verbosity ([EXST-5](#exst-5) owns the tap-side enforcement). Surfacing class-1 (and, at L3, clamped class-2) material on the [EXST-8](#exst-8) sinks is NOT a breach of subagent content-unobservability; the conversation-surface artefact rule is unchanged — see the telemetry carve-out under [SLSH-2](./slash-invocation.md#slsh-2).

## Author surface — the `theta_progress` tool (L3)

<a id="author-surface"></a> Layer L3 of [RFC 0010](../rfcs/0010-live-execution-visibility.md) (the RFC's hold gate discharged 2026-09-09: tool name and clamps ratified). The author-facing `theta_progress` tool is the class-2 producer [EXST-12](#exst-12) binds; the second reserved stdout key that carries a child-regime call across the process boundary is owned by [Subagent — PIC-74](./pi-integration-contract/subagent.md#pic-74); the milestone entry payload rides the [PIC-71](./pi-integration-contract/runtime-event-channel.md#pic-71) entry channel. The clamp values in [EXST-14](#exst-14) are normative — unlike the [EXST-6](#exst-6) tick they define what crosses a process boundary and what reaches the durable transcript, so they are part of the observable contract, not implementer tuning.

<a id="exst-13"></a> **EXST-13.** **The `theta_progress` tool.** The extension registers exactly one author-facing progress tool, named `theta_progress`, as an ordinarily-registered extension tool: one `pi.registerTool` registration per extension instance, inside the factory's synchronous entry path and **before** any compose pass resolves a callable set (so the `pi.getAllTools()` registry snapshot the `tools:` admission reads — [Parameters and Frontmatter — `tools:`](./frontmatter/frontmatter-fields-a.md#tools) — already carries the name), best-effort: a throwing registration draws the standard bootstrap diagnostic and MUST NOT abort factory registration or any theta's registration, and no new diagnostic code is minted ([DIAG-2](./diagnostics/diagnostic-shape.md#diag-2)). The tool's input schema is exactly `{ message: string, scope?: string, done?: integer, total?: integer }` with additional properties rejected. Argument validation is **ordinary tool-arg validation** per [Tool Calls — TOOL-1](./tool-calls.md#tool-1): a code-side call whose argument does not conform surfaces as the existing `Err(CodeToolError { cause: "validation", … })` arm, and a model-side call's non-conforming `tool_use` is fed back to the model as that block's failing tool result — neither path mints a diagnostic. The one unified callable-set entry serves theta code and the callee's model alike ([FRNT-2](./frontmatter/frontmatter-fields-a.md#frnt-2)): a model-issued call is admitted and MUST ride the same execution path and the same clamps as an author-written call ([EXST-14](#exst-14)). Execution MUST return the fixed success result — a single text block carrying the literal `ok`, never an error result — in both regimes, whether the call was accepted or dropped by the rate clamp; a call executing while no theta invocation is live in the executing process (the [`ActiveInvocationRegistry`](./pi-integration-contract/active-invocation-registry.md#active-invocation-registry) holds no entry) is a no-op that still returns `ok`.

<a id="exst-14"></a> **EXST-14.** **Parent-regime execution and the class-2 clamps.** When a `theta_progress` call executes in a process whose subagent-root regime is inactive ([Subagent — PIC-58](./pi-integration-contract/subagent.md#pic-58) marker absent — the parent regime), each **accepted** call MUST produce exactly two effects and nothing else: (a) one class-2 author-message publication on the execution-status bus, rendered on the [EXST-8](#exst-8) transient sinks under [EXST-6](#exst-6)'s coalescing tick; and (b) one durable milestone entry — `pi.appendEntry("theta-progress-entry", { milestone })` per [Runtime event channel — PIC-71](./pi-integration-contract/runtime-event-channel.md#pic-71) — carrying the clamped author fields plus best-effort class-1 attribution (`theta`, `invocation_id` — present only when the executing process attributes the call to a live registry entry, never invented). No `pi.sendMessage` ([EXST-1](#exst-1)), no wire line. When the entry channel is absent or degraded ([PIC-71](./pi-integration-contract/runtime-event-channel.md#pic-71) / [PIC-73](./pi-integration-contract/capability-probe.md#pic-73)) the milestone arm is skipped silently — the [PIC-72](./pi-integration-contract/runtime-event-channel.md#pic-72) message-channel fallback covers the three operator note classes only and MUST NOT be applied to milestones (degrade-to-fewer-sinks per [EXST-8](#exst-8)). The clamps — applied to the payload BEFORE any rendering or entry append, discharging [EXST-12](#exst-12)'s class-2 rate-and-length pin — are: `message` clamped to **200** characters and `scope` to **64** characters (the footer-clamp and name-clamp magnitudes); ANSI escape sequences and control characters stripped before the clamp is judged (a horizontal tab becomes one space); and a minimum inter-acceptance interval of **200 ms** per extension instance — a call arriving inside the interval is **counted-but-dropped** (no bus event, no entry, still returns `ok`), and the count of drops since the last accepted call MUST ride the next accepted publication and its milestone (the `dropped` field) and render as a dropped-count indicator. Under `theta.progress: off` ([EXST-10](#exst-10)) a call renders nothing and appends nothing (class-2 disabled entirely, [EXST-12](#exst-12)) while still returning `ok`.

<a id="exst-15"></a> **EXST-15.** **Child-regime execution — the wire arm.** When a `theta_progress` call executes in a process whose subagent-root regime is active ([Subagent — PIC-58](./pi-integration-contract/subagent.md#pic-58)), each accepted call MUST emit exactly one `theta_progress` reserved-key line on the process's own stdout and MUST touch nothing else — no UI surface, no execution-status bus publication, no entry append (the child's `--no-session` transcript is ephemeral; the wire line is the call's entire effect). The envelope shape, the fd-1 write discipline, the emission bounds, and the parent's ingest posture are owned by [Subagent — PIC-74](./pi-integration-contract/subagent.md#pic-74); the [EXST-14](#exst-14) clamps apply child-side before emission (length clamps, control/ANSI strip, the 200 ms inter-acceptance interval with the counted-but-dropped carry riding the next line's `dropped` field), and each process applies its **own** resolved `theta.progress` ceiling to its own arm — under `off` the child emits nothing. Parent-side, the tap ([EXST-5](#exst-5)) recognises the key in its own parse and publishes the re-clamped payload as a class-2 event attributed to the tapped child's invocation node — **transient sinks only**: a wire-ingested self-report MUST NOT be appended as a milestone entry (untrusted wire data stays off the durable transcript; RFC 0010 Erratum D records the narrowing). At L3 the wire crosses exactly one process boundary: a process that is itself a subagent child MUST NOT re-emit an ingested `theta_progress` line upward ([PIC-74](./pi-integration-contract/subagent.md#pic-74)'s no-relay clause; the upward relay is layer L4, deferred).
